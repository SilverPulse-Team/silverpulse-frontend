# Verificación FE-06 — Biblioteca de componentes UI y estados

Fecha de verificación técnica: 15 de noviembre de 2026.

## Resultado

| Criterio | Estado | Evidencia |
| --- | --- | --- |
| Los componentes reciben props tipadas y no realizan HTTP internamente | Cumple | La biblioteca expone interfaces y uniones TypeScript. La búsqueda de `fetch`, `axios` y `XMLHttpRequest` dentro de `src/components/ui` no devuelve usos. |
| Todos los estados pueden mostrarse sin APIs operativas | Cumple | La página técnica representa EmptyState, LoadingSkeleton, ErrorState y ConfirmationModal con estado local. |
| Los badges combinan texto e icono, nunca color como único indicador | Cumple | DataSourceBadge, QualityBadge, MissionPhaseBadge y SyncStatusBadge delegan en StatusBadge, que siempre renderiza icono y label accesible. |
| Las tablas se transforman en tarjetas/scroll controlado en móvil | Cumple técnicamente | ResponsiveDataTable usa tabla con scroll controlado desde 768 px y tarjetas apiladas por debajo de ese breakpoint. Pendiente revisión visual manual. |
| Se preservan unidad, fecha, fuente y calidad cuando el dato existe | Cumple | MetricCard usa una unión discriminada: cuando existe valor exige unidad, fuente, calidad, fase y fecha; `null` muestra «Sin datos». La tabla conserva los mismos metadatos por fila. |

## Casos demostrados

- Calidad `adequate`, `unknown` y `not_applicable`.
- Fuente `synthetic` visiblemente etiquetada.
- Fase `in_flight` con texto «Durante vuelo».
- Valor nulo de fuerza muscular como «Sin datos».
- Botón deshabilitado mientras `isSubmitting` es verdadero.
- Tabla desktop y representación móvil en tarjetas.
- Timeline que no marca como completados los eventos futuros.
- ChartPanel que se abstiene de dibujar una tendencia con una sola observación.
