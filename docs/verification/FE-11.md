# Verificación FE-11 — Cliente HTTP y manejo centralizado de errores

Fecha de verificación técnica: 15 de noviembre de 2026.

## Resultado

| Criterio | Estado | Evidencia |
| --- | --- | --- |
| La URL del backend es configurable sin editar componentes | Cumple | `VITE_API_BASE_URL` configura la base y usa `http://localhost:8000/api/v1` como fallback y ejemplo. |
| Los errores API se muestran sin fallos silenciosos | Cumple en la capa compartida | `ApiClientError` normaliza HTTP, timeout, cancelación, red, JSON inválido y respuestas fuera de contrato con mensajes aptos para UI. |
| El cliente no incluye credenciales ni secretos | Cumple | Usa `credentials: omit`; `.env.example` solo contiene configuración pública y README advierte que `VITE_*` nunca debe almacenar secretos. |
| La selección mock/HTTP es explícita y documentada | Cumple | `VITE_DATA_PROVIDER=mock|http`; ambos implementan `DataProvider` y se seleccionan exclusivamente en `getDataProvider()`. |
| GET `/health` no se representa como «Tierra conectada» | Cumple | Health solo existe como `getHealth`; el enlace se consulta de forma independiente mediante `getSimulatorStatus`. README documenta la diferencia. |

## Capacidades implementadas

- Cliente reusable con GET/POST tipados y query params.
- Timeout configurable de 10 segundos por defecto.
- Cancelación externa y timeout mediante `AbortController`.
- Mapeo específico de 400, 401, 403, 404, 409, 422 y 503.
- Diferenciación entre error HTTP, red, cancelación, timeout, JSON inválido y
  respuesta que no cumple OpenAPI v0.2.0.
- Parser obligatorio por operación; ninguna respuesta HTTP se afirma directamente
  como tipo genérico.
- Validadores de estructuras anidadas para nave, Tierra, simulador, catálogo,
  inbox y fuentes de investigación.
- Servicios separados: `ship`, `earth`, `simulator` y `research`.
- Métodos POST del simulador para configuración y avance, aunque todavía no los
  consume una pantalla.

  - respuesta 200 y construcción de query params;
  - mapeo de 400, 401, 403, 404, 409, 422 y 503;
  - conservación de detalle y código de error enviados por el backend;
  - rechazo de JSON malformado;
  - rechazo de respuesta que no cumple el parser;
  - timeout, aborto efectivo y señal ya cancelada antes de solicitar.

## Configuración local esperada

FastAPI debe aceptar CORS desde `http://localhost:5173`, métodos `GET`, `POST` y
`OPTIONS`, y el header `Content-Type`. La URL se define con:

```bash
VITE_DATA_PROVIDER=http
VITE_API_BASE_URL=http://localhost:8000/api/v1
```
